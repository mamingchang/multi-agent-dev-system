# Agent协作观察模式 - 完整指南

## 设计理念

我们的系统设计是**Agent之间自动协作**，而不是用户手动控制每一步。

### 两种模式对比

| 特性 | 观察模式 (watch) ⭐ | 手动模式 (run --interactive) |
|------|-------------------|---------------------------|
| Agent协作 | ✅ Agent自动讨论、质疑、修改 | ❌ 每个Agent后等待用户 |
| 用户角色 | 观察者 + 必要时仲裁 | 每步确认者 |
| 效率 | 高 - Agent自动收敛 | 低 - 需要频繁介入 |
| 适用场景 | 正常开发流程 | 学习/调试 |

## 观察模式 (推荐)

### 启动命令

```bash
# 观察模式 - Agent无法达成一致时介入
./cli/main.py workflow watch --project my-app

# 纯观察模式 - 自动批准所有决策
./cli/main.py workflow watch --project my-app --auto-approve
```

## 何时需要人工介入

系统会在以下情况自动请求人工介入：

### 1. 争议无法解决
- Agent之间争论超过3轮
- 无法达成一致

### 2. 需求不明确
- Requester发现需求描述不清晰
- 需要用户澄清

### 3. 严重偏离需求
- Agent的输出严重偏离原始需求
- 需要用户确认方向

### 4. 迭代次数超限
- 某个Agent重复执行超过5次
- 可能存在死循环

## 最佳实践

### 1. 使用观察模式

✅ **推荐：**
```bash
./cli/main.py workflow watch --project my-app
```

❌ **不推荐（除非学习/调试）：**
```bash
./cli/main.py workflow run --project my-app --interactive
```

### 2. 纯观察模式

如果你完全信任Agent，可以使用自动批准模式：

```bash
./cli/main.py workflow watch --project my-app --auto-approve
```

这样你只需要观察，不需要任何介入。

### 3. 提供清晰的需求

好的需求描述：
```
实现用户登录功能
- 支持邮箱和密码登录
- 包含"记住我"功能
- 要求支持1000并发
- 响应时间<200ms
- 密码必须加密存储
- 需要防暴力破解机制
```

不好的需求描述：
```
做一个登录
```

### 4. 信任Agent协作

- Agent之间的讨论是正常的
- 质疑和修改是协作的一部分
- 不要过早介入
- 只在真正需要时提供决策

## 与手动模式的区别

### 手动模式 (run --interactive)

```bash
./cli/main.py workflow run --project my-app --interactive
```

**特点：**
- 每个Agent完成后暂停
- 等待用户确认
- 用户控制每一步
- 适合学习和调试

**流程：**
```
Requester 完成 → [等待用户] → ProductManager 完成 → [等待用户] → ...
```

### 观察模式 (watch)

```bash
./cli/main.py workflow watch --project my-app
```

**特点：**
- Agent自动协作
- 自动讨论和修改
- 只在必要时介入
- 适合正常开发

**流程：**
```
Requester → ProductManager → [讨论] → [修改] → Architect → [讨论] → ...
                                                    ↓
                                            [无法解决] → 人工介入
```

## 总结

**观察模式 (watch)** 是我们设计的核心交互方式：

✅ Agent之间自动协作  
✅ 实时看到讨论过程  
✅ 只在必要时介入  
✅ 高效完成任务  

这才是真正的"AI Agent协作系统"！
