# 交互式工作流CLI使用指南

## 概述

交互式工作流CLI让你可以：
- 实时查看每个Agent的执行过程和输出
- 在Agent需要澄清时提供人工反馈
- 控制工作流执行（继续/重试/跳过/终止）
- 监控工作流实时状态

## 命令列表

### 1. 运行交互式工作流

```bash
./mas workflow run --title "任务标题" --description "详细需求"

# 或使用交互式输入
./mas workflow run
```

**交互模式特性**：
- Agent执行过程中会实时显示输出
- 当需求不清晰时，会暂停并等待你的反馈
- 当Agent之间有争议时，会请求你裁决
- 你可以随时介入控制流程

### 2. 人工决策选项

当工作流暂停等待你的决策时，你有以下选项：

#### continue - 继续执行
接受当前Agent的输出，继续到下一个Agent。

```
请选择操作 [continue]: continue
```

#### retry - 重试当前Agent
让当前Agent重新执行（例如，你修改了需求描述后）。

```
请选择操作 [continue]: retry
```

#### skip - 跳过当前Agent
跳过当前Agent，直接进入下一个Agent。

```
请选择操作 [continue]: skip
```

#### abort - 终止任务
终止整个工作流。

```
请选择操作 [continue]: abort
```

#### feedback - 提供反馈
提供具体的反馈内容，然后继续执行。

```
请选择操作 [continue]: feedback
请输入反馈内容: 单用户使用，无需登录。待办事项包含标题、描述、创建时间、完成状态。
```

### 3. 实时监控工作流

在另一个终端窗口中，你可以实时监控工作流的执行状态：

```bash
# 监控最新会话
./mas workflow monitor --latest

# 监控指定会话
./mas workflow monitor 084760cf

# 自定义刷新间隔（默认2秒）
./mas workflow monitor --latest --interval 5
```

## 完整工作流示例

### 场景：开发一个Todo应用

#### 步骤1：启动交互式工作流

```bash
./mas workflow run
```

输入任务信息：
- 任务标题：`开发Todo应用`
- 需求描述：`开发一个简单的Todo待办事项管理应用，用户可以添加、完成、删除待办事项`

#### 步骤2：Requester分析需求

系统会显示Requester的分析结果：
- 需求总结
- 清晰度和完整度评分
- 澄清问题列表

如果评分较低（<8分），系统会暂停并请求你的反馈。

#### 步骤3：提供澄清

```
请选择操作 [continue]: feedback
请输入反馈内容: 
单用户使用，无需登录
待办事项包含：标题、描述、创建时间、完成状态
用户可以添加、标记完成/未完成、删除待办事项
使用Web界面，响应式设计
技术栈：Python Flask + HTML + JavaScript + SQLite
```

#### 步骤4：继续工作流

Requester会根据你的反馈重新分析，如果评分提高到8+，工作流会自动继续到ProductManager。

#### 步骤5：监控进度（可选）

在另一个终端：
```bash
./mas workflow monitor --latest
```

实时查看每个Agent的输出。

#### 步骤6：完成

当所有Agent执行完成后，系统会显示：
```
================================================================================
✅ 工作流执行成功
================================================================================

消息: 任务执行完成
最终状态: completed

会话已保存: sessions/87654321-4321-4321-4321-210987654321.json
查看详情: ./mas task show 87654321
```

## 使用场景

### 场景1：需求不清晰，需要多轮澄清

```bash
# 1. 启动工作流
./mas workflow run

# 2. Requester发现需求不清晰，暂停
# 3. 你提供反馈
feedback: 补充具体需求细节

# 4. Requester重新分析
# 5. 如果还不够清晰，继续澄清
# 6. 直到评分达到8+，自动继续
```

### 场景2：Agent之间有争议

```bash
# 1. ProductManager设计了方案
# 2. Architect审查后提出反对
# 3. 争议超过3轮，升级到人工

# 你可以选择：
- continue: 接受ProductManager的方案
- retry: 让ProductManager重新设计
- skip: 跳过设计阶段
- feedback: 提供具体指导
```

### 场景3：实时监控长时间任务

```bash
# 终端1：运行工作流
./mas workflow run --title "大型项目" --description "..."

# 终端2：实时监控
./mas workflow monitor --latest

# 你可以看到：
# - 当前执行到哪个Agent
# - 每个Agent的输出
# - 任务状态变化
```

### 场景4：非交互模式（自动执行）

如果你的需求已经非常清晰，可以使用非交互模式：

```bash
./mas workflow run \
  --title "Todo应用" \
  --description "$(cat detailed_requirements.txt)" \
  --no-interactive
```

系统会自动执行，不会暂停等待人工介入。

## 工作流状态说明

| 状态 | 说明 |
|------|------|
| `created` | 任务已创建 |
| `in_requirement` | 需求分析阶段（Requester） |
| `in_design` | 设计阶段（ProductManager/Architect） |
| `in_development` | 开发阶段（Developer） |
| `in_review` | 审查阶段（CodeReviewer） |
| `in_testing` | 测试阶段（Tester） |
| `in_deployment` | 部署阶段（DevOps） |
| `completed` | 任务完成 |
| `rejected` | 任务被拒绝 |
| `failed` | 任务失败 |

## 人工介入触发条件

系统会在以下情况下暂停并请求人工介入：

1. **需求不清晰**
   - 清晰度评分 < 8/10
   - 完整度评分 < 8/10
   - 包含不确定的表述

2. **Agent迭代超限**
   - 单个Agent执行超过5次
   - 可能陷入死循环

3. **Agent争议无法解决**
   - Agent之间争议超过3轮
   - 需要人工裁决

4. **需求偏离**
   - Agent的输出严重偏离原始需求
   - 需要人工确认

## 技巧

### 1. 准备详细的需求文档

将需求写在文件中，然后传入：

```bash
./mas workflow run \
  --title "Todo应用" \
  --description "$(cat requirements.md)"
```

### 2. 使用tmux分屏

```bash
# 左侧：运行工作流
tmux new-session -s workflow
./mas workflow run

# 右侧：监控状态
tmux split-window -h
./mas workflow monitor --latest
```

### 3. 保存工作流日志

```bash
./mas workflow run --title "Todo应用" --description "..." 2>&1 | tee workflow.log
```

### 4. 查看历史会话

```bash
# 列出所有会话
./mas task list

# 查看特定会话的详细信息
./mas task show 084760cf

# 查看Agent状态
./mas task agents 084760cf
```

## 常见问题

### Q: 如何跳过人工介入，让工作流自动执行？

A: 使用 `--no-interactive` 选项：
```bash
./mas workflow run --title "..." --description "..." --no-interactive
```

### Q: 工作流卡住了怎么办？

A: 按 `Ctrl+C` 中断工作流。会话会被保存，你可以稍后查看：
```bash
./mas task show --latest
```

### Q: 如何提供更详细的反馈？

A: 选择 `feedback` 选项，然后输入多行文本（可以粘贴）：
```
请选择操作 [continue]: feedback
请输入反馈内容: 
需求补充：
1. 单用户使用，无需登录
2. 待办事项字段：标题、描述、创建时间、完成状态
3. 功能：添加、标记完成、删除
4. 技术栈：Python Flask + SQLite
5. 界面：响应式Web界面
```

### Q: 如何查看Agent的完整输出？

A: 使用task命令查看会话详情：
```bash
./mas task show --latest
```

这会显示所有Agent的完整输出，包括需求分析、设计方案、代码等。

### Q: 可以在工作流执行过程中修改需求吗？

A: 可以。当系统请求人工介入时，选择 `feedback` 并提供修改后的需求。Agent会根据新需求重新执行。
